Phase 1

Requirements Analysis

Objective: Identify nuclear medicine needs for low-dose PET scan enhancement and define functional software specs.

Activities Clinical literature review, paired DICOM dataset acquisition, defining metrics (PSNR, SSIM).
Deliverables System Requirement Specification (SRS) document, dataset protocol agreement.
Phase 2

System Planning

Objective: Establish deep learning framework (PyTorch), hardware requirements (Kaggle GPU), and project milestone schedule.

Activities Selecting U-Net architecture, environment configuration, web stack selection (Flask/Bootstrap).
Deliverables Capstone project plan, resource allocation map, risk assessment report.
Phase 3

System Design

Objective: Design neural network layers, Flask backend REST routes, and responsive healthcare UI components.

Activities U-Net encoder-decoder schema design, API endpoint contract definition, UI wireframing.
Deliverables System architecture diagram, database/schema specs, UI mockup layouts.
Phase 4

Implementation

Objective: Train U-Net model in Kaggle and code Flask web app backend and JavaScript dropzone UI.

Activities PyTorch training loop execution, weights saving (best_unet_pet.pth), Flask route integration.
Deliverables Trained model checkpoint, complete web codebase, image processing utils.
Phase 5

Testing

Objective: Validate image enhancement quality on unseen test dataset and verify web upload UI responsiveness.

Activities Quantitative PSNR/SSIM evaluation, DICOM parsing sanity checks, cross-browser UI testing.
Deliverables Final test results report, bug log, metric verification curves.
Phase 6

Deployment

Objective: Deploy production-ready web app to Render / Vercel cloud platform for live demonstration.

Activities Gunicorn WSGI server setup, environment variables configuration, Git repository push.
Deliverables Live web application URL, GitHub repository, deployment guide.
Phase 7

Maintenance

Objective: Monitor web app latency, handle new DICOM metadata tags, and update security dependencies.

Activities Performance monitoring, error logging inspection, model retraining planning for 3D volumes.
Deliverables Maintenance documentation, system update logs.

Why The Waterfall Model Was Selected

Chosen for this medical image enhancement project because of fixed clinical requirements, documentation needs, and sequential model → web validation.

1

Fixed Requirements Before Development

U-Net input/output tensor dimensions and loss functions were finalized during research before web coding began.

2

Medical Software Documentation Needs

Medical AI applications demand strict traceability across dataset split, training, and web inference.

3

Sequential Completion & Validation

Deep learning model training (Phase 4) must be complete and validated before backend web API integration.

4

Academic Capstone Management

Clear milestone deliverables and phase gates ideal for academic evaluation and progress monitoring.
